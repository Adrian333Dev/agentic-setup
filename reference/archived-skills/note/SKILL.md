# Note

Catch anything worth keeping the instant it surfaces — into `docs/work/inbox.md`, as-is. Don't decide where it belongs; that's `organize`'s job later. Deciding at capture time is the tax that makes capture get skipped.

## What goes in

- Any phase — brainstorm / build / research / debug.
- Anything worth keeping: decision, finding, gotcha, idea, reusable lesson, loose end. All mixed, no sorting.
- **Preferences too — inferred, not announced.** The user rarely says "this is my preference"; it surfaces as the same correction twice, or irritation at a habit. Catch it.
- **As long as it needs** — one line when concise, several when rich. Capture the whole thought; don't compress or pad.
- Raw is fine: a fragment, a pasted error, a half-formed idea.

## When

- Light background reflex — **not every turn**. Catch what's genuinely worth keeping; don't narrate routine thoughts.
- On request, immediately: "note that," "save that," `/note`.
- Unsure? Write it. Junk costs nothing (`organize` drops it); a lost insight costs the next session.

## Boundaries

- **To a file, not just chat** — chat gets compacted away. A short `[inbox]` confirmation is enough.
- **Create `inbox.md` lazily** — on first write only.
- **One exception:** an open `brainstorm.md` / `spec.md` owns its in-scope content. Send it only the strays that fall outside that document's scope.
- **No filing here** — routing is `organize`'s job. Inbox grown long? Suggest running it, in one line.
